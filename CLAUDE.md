# CO2Trace (repo: lca-carbon-ledger) — notes for Claude

- Single static page: `index.html` (inline CSS + JS, no build). Typography and motion follow abatable.com (2026-10-13): one family, Hanken Grotesk from Google Fonts (the free match for abatable's licensed PP Mori; to switch, license PP Mori, self-host it and put it first in the `--f-*` tokens), headings weight 500 with -.03em tracking, card titles 600, small uppercase labels with .06–.08em tracking, sentence-case buttons. The hero tree canvas uses the system monospace font. Smooth scrolling is Lenis 1.3.26 from jsDelivr (pinned, SRI) as `window.lenis`; use `goTo(el, 'center'?)` for in-page jumps. Lenis runs with `allowNestedScroll`, so an inner scroll box (like the sticky dashboard `.side`) scrolls first and then hands the wheel back to the page; don't put `data-lenis-prevent` or `overscroll-behavior: contain` on such boxes (that trapped the page over the dashboard until 2026-10-14). Only overlays that must keep the wheel (`#menu`, `#helpChat`, dialogs) carry `data-lenis-prevent`. Look: one brand blue #072AC8 (`--brand`: hero, top bar, titles `--title`, kickers `--kick`, Scope 1; `--hero-accent` #AFC0FF for accents on the blue band). Menu bar hovers white (`--menu-hover`), dashboard buttons hover blue (`--go`). Light page #EEF0EB with white 18px-radius cards. Scope colours are a blue scale; status green (`--ok`) is semantic only. The logo stays white.
- Data model (v: 2): `state = { v, company, year, fuName, fuQty, boundary, isExample, region ('us'|'mx'), method ('AR6'|'AR5'|'AR4'), goal{reason, app, audience, comparative, commissioner, practitioner, reportDate, refFlow, allocation, cutoff, exclusions, assumptions, review ('none'|'internal'|'external'|'panel'), reviewer, assurance ('none'|'limited'|'reasonable'), materiality (% string, default '5'), baseYear, baseTotal, priorTotal, recalc (% string, default '5'), recalcPolicy, s3 { '1'..'15': { d ('in'|'out'|'na'|''), why } }, rfc, scian, site, usStates, ca, rev1b}, rows[] }`; each row `{ id, stage, key, supplier, note, qty, unit, ef (kg CO2e/unit, used only when efEdit or key==='custom'), efEdit, scope, m0, m1 (activity months 0–11, inclusive; emissions spread evenly over them for the monthly chart), evidence: { doc, ref, period, verified, files[{fid,name,size,type,added}] }, dq?: { type, year, geo, tech } (blank = automatic), bio? (biogenic CO₂, kg per unit, memo) }`. Evidence file blobs live in IndexedDB db `lca-evidence`, store `files`, keyed by fid. Chart view choices (catView radial|treemap, catScope, ganttScope) live in localStorage `lca-ui-v1`.
- `STAGES`, `FACTORS`, `CATS` (emission categories = factor kind) and `DOCS` (evidence document types) are defined at the top of the script. Defaults: `defaultScope()`, `defaultDoc()`, `stageDefault()`.
- Factors store kg of each gas per unit, either `gas` (all countries) or `us`/`mx` (per country), plus `src`/`srcUs`/`srcMx`. `'CO2e'` is a pre-characterised pseudo-gas (LCI datasets, FESEN, edited factors). `GWP[method]` characterises; `emis(r)`, `gasT(r)`, `libEf(key)` do the math. eGRID2023 subregions are appended to `FACTORS` with `only: 'us'`. `V1_EF` lets v1 ledgers upgrade (a factor equal to its v1 library value becomes a library line).
- Country rules: México = RENE (AR5 for threshold and COA export, FESEN, certificates not recognised); US = GHG Protocol (Scope 2 location- and market-based via `s2Location`/`s2Market`, total uses market-based; HCFC-22 outside the scopes via `outside()`). Dashboard adds `complianceCard`, `checksCard`, `inventoryCard`; header has the Project setup panel (`renderSetup`).

- Databases (+ From database, `#dbDlg`): factor libraries in `data/libraries/*.json` (+ `index.json`), built from the publishers' downloads by `tools/libraries/build.py` (sources, licences and checks in `tools/libraries/README.md`): EPA supply chain v1.3, EXIOBASE 3.8.2, USLCI FY25 Q2 + US electricity baseline, AGRIBALYSE 3.2, WEEE LCI. The page fetches them lazily (works on co2trace.io, not in the artifact or from file://). A picked factor is copied into `state.lib[key]` (`{key, g, name, unit, kind, gas, lib, src, cite}`) and registered into `FACTORS`/`F` by `registerFactor()` at load, so rows keep working offline; `save()` prunes unused entries. Keys look like `uslci:xxxxxxxx`, `epa:331110`, `agb:6250`, `weee:…`, `exio:MX:12`. `MORE_GWP` adds the other Kyoto gases (SF6, NF3, PFCs, HFC-23/152a/236fa) to `GWP`; CSV/COA exports add a column per extra gas only when a line has it (`setGases()`). HCFC-22 traces are dropped from database factors. Never use EXIOBASE ≥3.9 (non-commercial). WEEE data may only be redistributed free of charge; BAFU needs a Nexus login and must stay in the background of a paid tool.

- Help chat (`#helpFab` + `#helpChat`, `helpChat()` near the end of the main script): no backend and no AI model. `KB` (2026-10-16) is the knowledge base of concepts, methodology and rules (footprint, GHGs/CO₂e, GWP, each scope, the 15 Scope 3 categories, organisational boundary, data to collect, calculation, spend vs activity data, the four LCA phases, each life-cycle stage, boundary, functional unit, cut-off, allocation, units, refrigerants, renewables/certificates, offsets/neutrality/net zero, SBTi targets, reduction, savings plan, ISO family, GHG Protocol vs ISO, EPD/PCR, verification/materiality, US and MX regulations, CBAM/CSRD, ISSB/CDP, why measure, land use/removals), each `{ p: exact phrases (normalised), k: keywords, en, es, x?: live extra, rel: ids in Q, acts }`, mapped by `toTopic` in front of the app topics in `TOPICS`. Matching in `answer()`: drops `STOP` words, weights keywords by rarity (1/DF), adds 2 + word count for an exact phrase; best score ≥ 0.15 wins. Answers with `rel` end with "Next questions" chips (`Q` holds the question texts); "Teach me the basics" walks the course. Regulatory answers say they are general information, not legal advice. When adding a topic, put the distinctive phrases in `p` (phrase words are not keywords) and test that the old questions still land where they should. `live.*` answers (total, hotspots, evidence, RENE) read `totals()` so they match the dashboard; answers can carry buttons that scroll to section ids. Add a topic when you add a feature. To make it a real AI assistant later, route questions through the backend (never put an API key in the page).

- Security (2026-10-14): a Content Security Policy sits in a `<meta http-equiv>` right after `<meta charset>` (GitHub Pages can't send headers). Inline scripts are allowed by SHA-256 hash, so **after editing any inline `<script>`, run `python3 tools/security/csp.py`** (`--check` exits 1 when stale); otherwise the browser silently refuses the edited script. Never add inline event handlers (`onclick=`) or `eval`; wire handlers in JS. New outside hosts must be added to `BASE` in that tool. Documents opened as blobs (the report, sample documents) inherit the policy, so they can't run their own scripts: the report's Print button is wired from the opener. Escape every user-entered value with `esc()` before it goes into HTML. `SECURITY.md` tells people to report problems through GitHub private vulnerability reporting. HTTPS has been enforced since 2026-10-14 (GitHub-managed certificate, auto-renewed), and the policy includes `upgrade-insecure-requests`. GitHub Pages can't send `frame-ancestors`, `X-Frame-Options` or HSTS headers for us, and the meta tag can't carry `frame-ancestors`.

When adding a goal field, it shows up in the read-only view automatically; give the examples a value for it.
